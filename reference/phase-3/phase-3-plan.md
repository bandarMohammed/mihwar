## 1. الفكرة باختصار

المرحلة الثانية خلّصت التصميم كامل: المتطلبات والشاشات وقاعدة البيانات والـ API والذكاء الاصطناعي والمهام. المرحلة الثالثة **نبرمج النسخة الأولى (MVP)** من هذي المستندات بالضبط، باستخدام **Claude Code** وعلى مستودع **GitHub** واحد.

- **نفس التقسيمة:** 4 مجموعات × 4 أعضاء، ونفس القادة.
- **كل مجموعة تمسك وحدات كاملة** (الخلفية والشاشات حقتها)، عشان تكون الملكية واضحة والتعارض أقل.
- **نبني Must أولًا** (56 مهمة). Should (10) بس بعد ما تخلص Must حقتك. Later (4) **ما تنبرمج** في هذي المرحلة.
- **ما نضيف شي مو في المهام.** أي نقص أو غموض ← سؤال للمنسق، ويتسجل في `docs/decisions.md`.

## 6. طريقة الشغل (لكل الأعضاء)

1. **مهمة وحدة لكل فرع ولكل Pull Request.** الفرع يطلع من **فرع مجموعتك** باسم `feature/T-230-short-name`، والـ Pull Request يروح **لفرع مجموعتك مو لـ `main`**. رسالة الـ commit تبدأ برقم المهمة `T-230: …`.
2. **قبل ما تبدأ:** حدّث فرع مجموعتك، وتأكد إن المهام اللي «يعتمد عليها» مدموجة فيه أو في `main`. لو لا، اشتغل على بيانات تجريبية أو اسأل قائدك.
3. **Claude Code يقرأ `CLAUDE.md` تلقائيًا** ويمشي على «How to work on a task». أنت تراجع كل سطر قبل الـ PR.
4. **لكل معيار قبول اختبار**، والـ PR فيه قائمة المعايير وكيف تحققت من كل واحد.
5. **الصلاحيات في الخادم دائمًا**، مو بس إخفاء زر. مدير القسم يشوف قسمه بس.
6. **كل شاشة فيها الحالات الخمس:** loading · success · error · empty · no-permission، وعربي RTL بألوان `docs/design-system.md` فقط.
7. **ممنوع:** رفع كلمات مرور أو مفاتيح (`.env`) · تعديل ملفات `docs/` بدون موافقة المنسق · البناء على قرار مكتوب `proposed` بدون ما تسأل.
8. **الأسماء** (الحالات والأولويات والأقسام والأدوار) من `docs/glossary.md` حرفيًا.

### 6.1 الفروع في GitHub

| الفرع | يطلع من | مين يدمج فيه |
|---|---|---|
| `main` | — | المنسق بس |
| `group-1-wasl` · `group-2-shell` · `group-3-core` · `group-4-ai` | `main` | قائد المجموعة |
| `feature/T-xxx-…` (فرع لكل مهمة) | فرع مجموعتك | — ينحذف بعد الدمج |

1. العضو يسوي فرع مهمته من فرع مجموعته، ويبرمج، ويفتح Pull Request **على فرع مجموعته**.
2. القائد يراجع حسب «قائمة تحقق القائد» في دليل المجموعة، ويدمج.
3. المنسق يدمج فرع المجموعة في `main`.

**ثلاث قواعد عشان ما تتراكم التعارضات:**
- المنسق يدمج كل فرع مجموعة في `main` **كل يومين على الأقل**، ويدمج **فورًا** التسليمات اللي الكل ينتظرها: T-080 · T-001 · T-101 · T-102 · T-030 · T-260.
- بعد كل دمج في `main`، **القائد يحدّث فرع مجموعته من `main`**، عشان مجموعته تشوف شغل المجموعات الثانية.
- كل فروع المجموعات و`main` محمية: ما يدخلها شي إلا بـ Pull Request وموافقة، وممنوع حذفها أو الكتابة فوق سجلها.
