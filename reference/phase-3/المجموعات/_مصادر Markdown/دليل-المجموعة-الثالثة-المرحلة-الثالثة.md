## 1. مهمتنا باختصار

نبني الأساس اللي يعتمد عليه الكل: المستودع والبيئة والفحص التلقائي، وقاعدة البيانات، وتسجيل الدخول وفحص الصلاحيات في الخادم، وإدارة المستخدمين والأدوار والإعدادات، وفي الأخير اختبار الصلاحيات والتكامل للنظام كامل.

- **مهامنا:** 17 مهمة — Must 16 · Should 1 · Later 0.
- **القائد:** العضو 1 — يوزّع ويتابع ويراجع ويدمج، ويرسل للمنسق تقرير نهاية كل أسبوع.
- **المخرج النهائي:** كل مهام Must مدموجة في `main` ومعايير قبولها ناجحة، وتشتغل مع شغل المجموعات الثانية.
- **فرع مجموعتنا في GitHub:** `group-3-core` — كل Pull Request يروح له مو لـ `main`. القائد يدمج فيه، والمنسق يدمجه في `main`.

## 5. قواعد مهمة لمجموعتنا

- أنتم أول خطوة في الخطة: أي تأخير عندكم يأخّر الـ 16 عضو. القائد يتابع يوميًا في الأسبوع الأول.
- كلمات المرور: 8 أحرف على الأقل، وبعد 5 محاولات فاشلة يتوقف الدخول 15 دقيقة (✅ Q-4102)، والقيم من الإعدادات.
- الصلاحيات من جدولي `permissions` و`role_permissions` (✅ ADR-3101)، ومدير القسم يشوف قسمه بس.
- مهمة وحدة لكل فرع ولكل Pull Request، والـ Pull Request على `group-3-core`. والأسماء من `docs/glossary.md`، والصلاحيات تنفحص في الخادم.
- **قرارات المنسق اللي تأثر علينا:** الاستضافة وقواعد GitHub (T-080 · T-081)، ومكان حفظ جلسات الدخول (T-101 · T-003).

## 7. قائمة تحقق القائد قبل دمج أي Pull Request

- [ ] الـ PR لمهمة وحدة، **وهدفه `group-3-core`**، والفرع والـ commits برقمها (`T-xxx`).
- [ ] كل معيار قبول للمهمة مذكور في الوصف، ومعه اختبار ناجح.
- [ ] الفحص التلقائي (CI) أخضر.
- [ ] الصلاحيات تنفحص في الخادم (جرّب بحساب دور ثاني).
- [ ] الشاشة عربية RTL، فيها الحالات الخمس، وبألوان ومكوّنات `docs/design-system.md`.
- [ ] الأسماء من `docs/glossary.md`، وما فيه كلمات مرور أو مفاتيح مرفوعة.
- [ ] ما تغيّر شي في `docs/` بدون موافقة المنسق، وما انبنى شي على قرار `proposed`.

**برومت القائد للمراجعة:**

> أنا قائد المجموعة 3 بمشروع محور. راجع الـ Pull Request رقم [..] للمهمة [T-xxx] حسب «قائمة تحقق القائد» في دليل مجموعتي و`docs/acceptance-criteria.md`، وأعطني تقرير: وش ناجح، ووش ناقص، ووش لازم يتعدل قبل الدمج.
