## 1. مهمتنا باختصار

نبني الإطار العام اللي تنبني داخله كل الشاشات (القائمة الجانبية والثيمين والحالات الخمس)، واللوحات الأربع وصفحة «حسابي»، ومعالجة الطلبات في الأقسام، والإشعارات وسجلات النظام.

- **مهامنا:** 17 مهمة — Must 14 · Should 2 · Later 1.
- **القائد:** العضو 1 — يوزّع ويتابع ويراجع ويدمج، ويرسل للمنسق تقرير نهاية كل أسبوع.
- **المخرج النهائي:** كل مهام Must مدموجة في `main` ومعايير قبولها ناجحة، وتشتغل مع شغل المجموعات الثانية.
- **فرع مجموعتنا في GitHub:** `group-2-shell` — كل Pull Request يروح له مو لـ `main`. القائد يدمج فيه، والمنسق أو لينا الطلحي يدمجونه في `main`.
- **مين يدمج:** الأعضاء يرفعون ويفتحون Pull Request ويراجعون شغل بعض **وما يدمجون** · القائد يدمج في فرع مجموعتنا بس · المنسق ولينا الطلحي بس يدمجون في `main`. والذكاء الاصطناعي يسوي دور الشخص اللي يساعده بس.

## 7. قائمة تحقق القائد قبل دمج أي Pull Request

- [ ] الـ PR لمهمة وحدة، **وهدفه `group-2-shell`**، والفرع والـ commits برقمها (`T-xxx`).
- [ ] كل معيار قبول للمهمة مذكور في الوصف، ومعه اختبار ناجح.
- [ ] الفحص التلقائي (CI) أخضر.
- [ ] الصلاحيات تنفحص في الخادم (جرّب بحساب دور ثاني).
- [ ] الشاشة عربية RTL، فيها الحالات الخمس، وبألوان ومكوّنات `docs/design-system.md`.
- [ ] الأسماء من `docs/glossary.md`، وما فيه كلمات مرور أو مفاتيح مرفوعة.
- [ ] ما تغيّر شي في `docs/` بدون موافقة المنسق، وما انبنى شي على قرار `proposed`.
- [ ] الدمج يكون منك أنت في فرع المجموعة بس، ولا تدمج في `main`.

**برومت القائد للمراجعة:**

> أنا قائد المجموعة 2 بمشروع محور. راجع الـ Pull Request رقم [..] للمهمة [T-xxx] حسب «قائمة تحقق القائد» في دليل مجموعتي و`docs/acceptance-criteria.md`، وأعطني تقرير: وش ناجح، ووش ناقص، ووش لازم يتعدل قبل الدمج. لا تدمج إلا لما أقول لك، وفي فرع مجموعتنا بس.

**برومت العضو لمراجعة شغل زميله:**

> أنا عضو في المجموعة 2. راجع الـ Pull Request رقم [..] لزميلي حسب معايير قبول مهمته في `docs/acceptance-criteria.md`، واقترح لي تعليقات أكتبها. لا توافق ولا تدمج عني، أنا أضغط Approve أو Request changes بنفسي.
