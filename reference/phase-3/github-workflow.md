# طريقة العمل على GitHub — محور

> **لكل الأعضاء الـ 16 · المرحلة الثالثة.** المستودع: `github.com/bandarMohammed/mihwar`
> اقرأه مرة وحدة قبل أول مهمة. ولو نسيت خطوة، Claude Code يقدر يسويها معك: قل له «سو الخطوة رقم … من طريقة العمل على GitHub».

## 1. شكل الفروع

| الفرع | يطلع من | مين يدمج فيه |
|---|---|---|
| `main` | — | المنسق ولينا الطلحي بس |
| `group-1-wasl` · `group-2-shell` · `group-3-core` · `group-4-ai` | `main` | قائد المجموعة |
| `feature/T-xxx-…` (فرع لكل مهمة) | فرع مجموعتك | — ينحذف بعد الدمج |

| المجموعة | فرعها |
|---|---|
| 1 · وصل | `group-1-wasl` |
| 2 · الإطار والأقسام والإشعارات | `group-2-shell` |
| 3 · الأساس والمستخدمون | `group-3-core` |
| 4 · العقل التشغيلي والذكاء الاصطناعي | `group-4-ai` |

**القاعدة باختصار:** كل مهمة لها **فرع صغير** يطلع من **فرع مجموعتك**، ويرجع له بـ **Pull Request**. ما أحد يرفع على `main` أو على فرع المجموعة مباشرة، وGitHub يمنعه أصلًا.

### مين يسوي وش

| مين | يرفع فرعه ويفتح Pull Request | يراجع (Approve أو Request changes) | يدمج في فرع المجموعة | يدمج في `main` |
|---|---|---|---|---|
| العضو | نعم | نعم، شغل زملائه | **لا** | **لا** |
| القائد | نعم | نعم | نعم (فرع مجموعته بس) | **لا** |
| المنسق (بندر) ولينا الطلحي | نعم | نعم | نعم | نعم |

⚠️ **هذي قاعدة الفريق.** GitHub يسمح تقنيًا لأي أحد عنده صلاحية يضغط Merge بعد الموافقة، فالالتزام علينا. وكل دمج مسجّل باسم اللي سواه.

**والذكاء الاصطناعي (Claude Code أو غيره) يسوي دورك أنت بس:** عند العضو يجهّز الفرع والـ Pull Request ويراجع لو طلبت، **وما يدمج أبدًا**. وعند القائد يدمج في فرع مجموعته بس لما يطلب منه القائد صراحة. وما يدمج في `main` إلا للمنسق أو لينا. القاعدة مكتوبة في `CLAUDE.md`، فلو طلبت منه يدمج وأنت عضو، بيرفض.

## 2. أول مرة بس

1. سو حساب على GitHub، وأرسل **اسم المستخدم** لقائدك.
2. اقبل **الدعوة** اللي توصلك على الإيميل أو في GitHub (تنتهي بعد 7 أيام).
3. ثبّت **Git** و**VS Code** و**Claude Code**، وسجّل دخولك في GitHub من VS Code.
4. نزّل المستودع في مجلد عادي على جهازك (مو داخل OneDrive):

- `git clone https://github.com/bandarMohammed/mihwar.git`

5. افتح مجلد `mihwar` في VS Code.

## 3. كل مهمة (العضو)

**1. روح لفرع مجموعتك وحدّثه** (بدّل `group-1-wasl` بفرع مجموعتك):

- `git checkout group-1-wasl`
- `git pull`

**2. سو فرع المهمة منه** (رقم مهمتك واسم قصير بالإنجليزي):

- `git checkout -b feature/T-230-submit-form`

**3. برمج مع Claude Code** بالبرومت الجاهز في دليل مجموعتك. راجع كل اللي يكتبه وافهمه.

**4. احفظ شغلك** (الرسالة تبدأ برقم المهمة):

- `git add .`
- `git commit -m "T-230: add request form"`

**5. ارفع فرعك:**

- `git push -u origin feature/T-230-submit-form`

**6. افتح Pull Request** من صفحة المستودع (يطلع لك زر «Compare & pull request»):
- **base:** فرع مجموعتك (`group-1-wasl`) — **مو `main`** ⚠️
- **compare:** فرع مهمتك
- العنوان: `T-230 · شاشة تقديم الطلب`
- الوصف: كل معيار قبول للمهمة (من `docs/tasks.md`) وكيف تحققت منه.

**7. لو القائد أو زميلك طلب تعديل:** عدّل على **نفس فرعك**، وسو commit وpush مرة ثانية. الـ Pull Request يتحدث لحاله.

**8. لا تدمج بنفسك:** القائد هو اللي يدمج. بعد الدمج ارجع للخطوة 1 وابدأ مهمتك الجاية من فرع المجموعة المحدّث.

### مراجعة شغل زميلك (العضو)
1. افتح Pull Request زميلك ← تبويب **Files changed**.
2. قارن بمعايير قبول المهمة في `docs/tasks.md`، واكتب ملاحظتك على السطر.
3. اختر **Approve** لو تمام، أو **Request changes** لو فيه شي. **ولا تضغط Merge.**

## 4. القائد

**مراجعة Pull Request من عضو:**
1. افتح الـ Pull Request ← تبويب **Files changed** ← راجع حسب «قائمة تحقق القائد» في دليل مجموعتك.
2. لو فيه شي: اكتب تعليق على السطر، واختر **Request changes**.
3. لو تمام: **Approve** ← ثم **Merge** ← ثم **Delete branch**. (الدمج في فرع مجموعتك بس، ولا تدمج في `main`.)

**بعد كل دمج من المنسق في `main`** (عشان مجموعتك تشوف شغل المجموعات الثانية):
1. افتح **New pull request** ← **base:** فرع مجموعتك · **compare:** `main`.
2. عضو من المجموعة يوافق، وأنت تدمج.

**نهاية كل أسبوع:** رسالة للمنسق: وش اندمج · وش متأخر · وش ننتظر من مجموعة ثانية.

## 5. المنسق ولينا الطلحي

- يراجعون ويدمجون كل فرع مجموعة في `main` **كل يومين على الأقل** (Pull Request: base `main` · compare فرع المجموعة).
- يدمج **فورًا** التسليمات اللي الكل ينتظرها: T-080 · T-001 · T-101 · T-102 · T-030 · T-260، ويبلّغ القادة يحدّثون فروعهم.

## 6. لو صار شي

| المشكلة | الحل |
|---|---|
| فتحت Pull Request على `main` بالغلط | في صفحة الـ Pull Request اضغط **Edit** جنب العنوان، وغيّر **base** لفرع مجموعتك |
| GitHub يقول «Changes must be made through a pull request» | أنت ترفع على فرع محمي. سو فرع مهمة (الخطوة 2) وارفع عليه |
| GitHub يقول فيه **conflict** | قل لـ Claude Code: «حدّث فرعي من فرع المجموعة وحل التعارض»، وراجع الحل قبل الرفع. لو ما وضح، اسأل قائدك |
| نسيت تحدّث فرع المجموعة قبل ما تبدأ | `git checkout group-…` ثم `git pull`، ثم ارجع لفرعك وقل لـ Claude Code يدمج التحديث فيه |
| رفعت ملف فيه مفتاح أو كلمة مرور بالغلط | بلّغ المنسق **فورًا**. لا تحاول تحذفه لحالك، لأن المفتاح لازم يتغيّر |
| ما تشوف فرع مجموعتك | `git fetch` ثم `git checkout group-…` |

## 7. ممنوع

- الرفع المباشر على `main` أو على فرع مجموعة.
- فرع فيه أكثر من مهمة، أو Pull Request فيه أكثر من مهمة.
- رفع `.env` أو مفاتيح أو كلمات مرور.
- تعديل ملفات `docs/` بدون موافقة المنسق.
- الدمج لأي أحد غير القائد (في فرع مجموعته) والمنسق ولينا (في `main`).
- تخلي الذكاء الاصطناعي يدمج بدالك.
